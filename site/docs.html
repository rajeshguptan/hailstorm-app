Getting Started

Installation

Hailstorm is an Electron desktop API client. Install the application for your platform, launch it locally, and start building requests without creating an account.

  • Desktop app built with Electron, Vue 3, Pinia, and Vite.
  • Local-first storage for collections, environments, history, secrets, and settings.
  • Developer Tools are disabled by default and can be enabled from Settings > Advanced > Developer Tools.

Getting Started

Quick Start

Create a request, choose an environment, send it, and inspect the response from a single workspace.

  1. Create or import a collection. Add folders and requests from the Collections sidebar.
  2. Configure the request. Set method, URL, parameters, headers, body, auth, variables, scripts, or Markdown description.
  3. Send and inspect. Review response body, headers, cookies, timing, and test assertion output.

Getting Started

Workspace Layout

Hailstorm uses a compact left ribbon for major views, an optional resizable sidebar for workspace content, and a flexible main content area for request/response work or full-screen utilities.

Ribbon

Collections, History, Secrets, Stats, Runner, Console, Docs, and Settings.

Sidebar

Resizable workspace area for collections, history, secrets, and run configurations.

Request editor

Tabs for parameters, auth, headers, body, variables, scripts, and description.

Response panel

Inspect response body, headers, cookies, timing, and tests after execution.

Request Types

HTTP Requests

Build REST and HTTP API requests with methods, URL parameters, headers, body editors, auth, variables, and scripts.

Methods

GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS, and custom methods.

Bodies

JSON, form data, URL encoded, raw, binary, none, and GraphQL-specific payloads.

Network controls

Request timeout, max response size, redirect following, SSL verification, and proxy settings.

Substitution

URLs, headers, body content, auth, scripts, and certificates resolve environment and request variables.

Request Types

GraphQL Requests

GraphQL requests use a POST method, JSON body, operation name, variables, and the same auth, headers, variables, and scripts as HTTP requests.

  • GraphQL body type switches the editor to query, variables, and operation name fields.
  • Use environment variables in queries, variables, headers, and auth.
  • GraphQL responses are inspected in the normal response panel.

Request Types

JSON-RPC Requests

JSON-RPC requests are stored as POST requests with JSON body content and a request flag that renders an RPC badge in the collection tree.

  • Use JSON body content for method, params, id, and JSON-RPC version.
  • Mark requests with Request.isJsonRpc for clear collection-tree identification.
  • Combine with variables and scripts for dynamic ids, auth headers, and payloads.

Request Types

WebSocket Connections

Connect to WebSocket endpoints, send JSON, XML, or text messages, and inspect live frames through the response and console workflow.

  • WebSocket requests use isWebSocket and route through the WebSocket execution path.
  • Message body types include JSON, XML, and text.
  • Useful for streaming APIs, chat services, and real-time event streams.

Request Types

Shell Commands

Run local shell commands from the request editor when a request method is set to SHELL. The URL field acts as the command input and the editor switches to a shell detail view.

Workflow

Collections

Organize requests into collections and folders with context-menu actions for adding, copying, pasting, duplicating, renaming, importing, and deleting.

Request actions

Add HTTP, JSON-RPC, GraphQL, WebSocket, and shell requests from collection or folder context menus.

Import

Import Postman JSON collections and OpenAPI/Swagger specs. OpenAPI operations are grouped by tags into folders.

Recent requests

Recently opened requests appear as compact tabs at the bottom of the Collections view.

Workflow

Authentication

Apply request-level authentication for common API security schemes and inherit auth from parent requests when useful.

Supported auth

Bearer token, Basic, NTLM, API key, OAuth 2.0, client certificate, and inherit from parent.

API key placement

API keys can be sent in request headers or query parameters.

Client certificates

PKCS#12 and PEM certificate/key pairs can be selected from disk.

OAuth 2.0

Authorization code flow with PKCE, token URL, client credentials, scopes, redirect URI, access token, and refresh token storage.

Workflow

Environments and Variables

Switch between dev, staging, production, or custom environments without changing request definitions.

  • Global variables are available across collections and environments.
  • Environment variables are scoped to the selected environment.
  • Request variables can target all environments or one specific environment.
  • Variables are substituted into URLs, headers, body content, auth, scripts, and certificates.

Workflow

Scripts and Assertions

Use JavaScript to prepare requests, validate responses, generate signatures, chain dependent calls, and document request behavior.

Pre-request scripts

Generate timestamps, HMAC signatures, tokens, headers, and dynamic request data before execution.

Test scripts

Assert status codes, response time, headers, JSON structure, and custom response conditions.

Descriptions

Markdown descriptions keep API notes next to requests and collections.

Workflow

Secrets and Privacy

Store sensitive values locally with encryption. The Secrets list shows names only; detail view reveals values after unlocking.

  • Secrets are encrypted before being stored on disk.
  • An encryption key is required to unlock, add, edit, import, or export secrets.
  • Secret detail supports name, environment, and value.
  • Collections, environments, history, and settings remain local-first.

Automation

Runner

Create run configurations that select requests from a collection and execute them as automated workflows.

  • Select a collection and choose requests to include in a run configuration.
  • Configure run mode, delay, iterations, and repeated execution.
  • Runner details show selected requests and active environment context.
  • Run configurations are managed from the Runner sidebar.

Automation

Load Testing

Scale selected requests into concurrent load tests with worker threads, live telemetry, and persisted run results.

Execution controls

Configure virtual users, duration, ramp-up, request rate, and request selection.

Live telemetry

Track total requests, successful requests, failed requests, average response time, and requests per second.

Per-request metrics

Record request counts, errors, latency, response size, timestamp, and optional detail chunks.

Persistence

Completed runs are stored locally, selectable in Stats, exportable as JSON, and deletable.

Automation

Stats and Charts

Review aggregated metrics, per-request breakdowns, and response-time percentiles after or during a run.

  • Requests vs Time: aggregated or per-request request counts.
  • Errors vs Time: 5xx failures by time bucket or request name.
  • Response Time: mean, p50, p75, p90, p95, and p99 percentiles.
  • Stats supports current live run, completed run selection, JSON export, and deletion.

Automation

History and Console

History captures sent requests for review and reuse. Console provides a full-screen view for runtime messages and debugging output.

  • History stores method, URL, headers, body, auth, variables, scripts, and timestamp.
  • Recent request tabs appear at the bottom of Collections.
  • Console is available from the ribbon as a full-screen utility view.

Settings

Settings

Customize UI behavior, application defaults, network settings, proxy, certificates, global variables, secrets, and developer tools.

User Interface

Theme, font sizes, layout, auto-save, recent request count, and keyboard shortcuts.

Application

Network timeout, max response size, redirects, SSL verification, proxy, certificates, and global variables.

Advanced

Secrets encryption key management, Developer Tools toggle, shortcut reference, and About panel.

Troubleshooting

Troubleshooting

Use these checks when a request, environment, secret, or load test does not behave as expected.

Request fails to send

Check URL, method, proxy, SSL verification, timeout, and variable substitution. Use Developer Tools only when needed.

Secrets are locked

Open Secrets and enter the encryption key. If the key is lost, encrypted secret values cannot be recovered.

Load test has no charts

Start a run from Runner and wait for the load testing service to record request metrics. Stats charts update from live rolling windows and completed run data.
